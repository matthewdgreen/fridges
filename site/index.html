04 / Read the fine print

Cold facts.
Clear limitations.

A quiet news cycle is not an all-clear.

What does “No” mean?

This is an editorial assessment of the reported attacks and continuing exposure, not a live test of every fridge. It does not automatically turn to “Yes” after a quiet stretch.

What resets the counter?

A reviewed, substantial attack wave that disrupts refrigeration at multiple sites. We use the incident date, not the date of a later article. Suspected incidents are labeled; a new headline about an old incident does not reset the clock. Days use UTC calendar dates.

What does the Shodan number measure?

The prominent baseline counts distinct IP addresses with at least one matching service not tagged by Shodan as a honeypot; the small-print totals include tagged service records. An IP with both tagged and untagged records remains eligible. The exposure history retains unfiltered historical totals, while the firmware chart excludes tagged honeypots by default. All counts are matching internet service banners, worldwide, for http.title:"Danfoss StoreView". It is a narrow fingerprint, not all Danfoss products. Multiple ports can inflate the total; one controller can serve many fridges. Shodan's index also lags real-world changes. Download distinct-IP history ↗ · API methodology ↗

What did the one-off landing-page measurement find?

On 3 November 2026, a separately authorized active measurement made one ordinary unauthenticated request to / at one cached endpoint for each of 2,050 eligible IPs. It recognized 212 StoreView landing pages; 1,409 requests timed out and 332 had TLS failures. The remaining 97 produced other pages, responses or errors. Another 51 IPs had no eligible cached endpoint. There were no retries, redirect following, logins, scripts or controller changes.

This is a conservative observation, not a complete live-device count: timeouts and TLS failures do not establish that equipment is offline. Among recognized pages, 205 retained the cached firmware inference and seven differed or became unknown; this does not establish seven upgrades. Visible UI versions are not controller firmware. A later code audit reproduced an undercount risk: the original reader could receive a valid title, then time out waiting for more body data. The number of affected timeouts cannot be recovered, so 212 is only the number recognized by that checker. The checker has since been corrected and tested locally; this measurement has not been rerun.

A later cached Shodan query found 106 IPs with honeypot-tagged StoreView records. The original filter excluded tagged records, rather than every IP with any tagged record. The overlap between those IPs and the 212 recognized pages is unknown because no IP-to-outcome linkage was retained. Download the cached honeypot audit ↗. Only aggregate results are retained. How does this stay up to date?

GitHub Actions requests aggregate Shodan IP, service and firmware counts daily at 11:17 UTC and saves their dated history. News is reviewed separately each day by a scheduled Codex task; its last completed review is shown above. Failed collections preserve prior data and show its age. Historical published snapshots remain separate from our own samples.

How can operators reduce exposure?

Follow the manufacturer's and your national CERT's guidance: restrict access to management interfaces, use protected remote access, and apply supported updates. Internet exposure does not by itself identify an exploited vulnerability. Read CERT-FR's advisory ↗ · ENISA’s national advisory collection ↗
